Building a reliable skill

Choose a repeated task. Define a useful result. Test it, give feedback and check it again.

Laurence Wood

AI Training Facilitator · Affinda Deployment

Try it yourself

Draft a skill of your own

The main aim is to create a first draft of your skill using Step 2. If you have time, describe a realistic example you could use to test it and what a useful result would look like. Running the test and inspecting its output are optional if time allows.

If you already have a small, repeatable workflow you understand well, start at Step 2. Otherwise, use Step 1 to help you choose and scope one.

Work on your skill draft using Step 2. Use Step 3 to plan a realistic test if you have time. Continue in the same conversation and review each response before moving on. You can return to the testing and refinement prompts after the session. Try the saved skill in a fresh chat, without the examples and corrections from the chat where you built it.

Replace the text in square brackets with your own details. If skill creation isn’t available, prompt 2 asks for a draft you can develop further.

Step 1

Choose and scope the workflow

Copy prompt 1

Choose a repeated task you understand well enough to review. Use an existing conversation with a completed task, or describe a task you do regularly. Read the options and choose one you can assess.

Help me identify a small, repeatable workflow for a skill.

Use the tasks or examples available in this conversation or
accessible sources. Say what you used. If there isn’t enough
context, ask me to describe one task I do regularly.

Suggest up to three options. For each, explain:
- The specific job and required inputs
- The output I would receive
- What is outside its scope
- How I could check whether it worked

Recommend one manageable option for a first attempt.

Step 2

Define success and create the first draft

Copy prompt 2

Replace [option or workflow] with your choice. Read the proposed checks. If they say “high quality”, “professional” or “accurate”, ask what that means for your task.

I choose [option or workflow].

Define a useful result and up to five observable checks.
Include what should happen when information is missing or
the request cannot be completed. Ask up to two essential questions.

Then use the available skill-creation workflow to create a small
first version. Include when to use it, inputs, steps, output
requirements and review checks.

If skill creation isn’t available here, draft the SKILL.md content
and explain what remains to make it usable.

Distinguish reusable instructions from requirements for this example.

Step 3

Plan a test; run it if time allows

Copy prompt 3

Check that your planned test reflects a task you would actually use the skill for. If you run it, inspect the result yourself and note one thing it handled well or one thing you would change.

Suggest one realistic example I could use to test my skill. Describe the input, what a useful result would look like and what I should check. Do not run the test yet.

If I ask you to run it, keep the actual output. Compare it with the source and agreed checks. Report what passed, what failed and what remains uncertain, with specific evidence. Confirm whether the skill was actually used, if observable.

Don’t change the skill during this first test.

After the session

Refine and check again

Copy prompt 4

Replace [feedback] with your own observations. Review the proposed change and agree it before continuing. Compare the new result with an earlier case.

Here is my feedback: [feedback].

Identify the reason behind the correction. Propose the smallest
useful skill change and explain whether it applies generally
or only to this case.

Apply the agreed change, rerun the relevant case and test an
earlier case. Keep the actual results and flag unresolved issues.

Before you finish

What must a useful result preserve?
What would you test next?

Your first draft will still need testing and review before you rely on it.
